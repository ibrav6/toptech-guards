# قمم — نظام الهوية والواجهات

**`@toptech/ui` · العربية أولاً · React · الإصدار 0.1.0**

مكتبة واجهات قابلة للتثبيت، ومعرض للهوية، وStorybook، وبوابة للسلوك
والصور والإتاحة والأداء. المكوّنات الأساسية مقتبسة من shadcn/ui ومبنية على
Radix؛ نحن نملك تنسيقها وعقود استخدامها. صفحة المساعدة أول مستهلك تجريبي؛ ترحيل بقية الموقع مهمة لاحقة.

## البداية

Node 22، وnpm، وDocker على macOS/Windows للمقارنات البصرية الموحّدة.
على Linux استعمل صورة CI المثبّتة `mcr.microsoft.com/playwright:v1.63.0-noble`.

```bash
cd design-system
npm ci
npx playwright install chromium firefox webkit
npm run build
npm run build:gallery
npm run preview
```

المعرض: `http://127.0.0.1:4178` — هوية، أسس، مكوّنات، قوالب، ودليل.
لتطوير المصدر: `npm run build` بعد تعديل المكوّنات ثم `npm run dev`؛
المعرض **يستهلك الحزمة المخبوزة** عمداً كي لا ينجح المصدر ويُشحن إصدار معطوب.

```bash
npm run build:storybook
npm run storybook
```

Storybook: `http://127.0.0.1:6008`، مع تبديل المظهر والاتجاه وفحص الإتاحة.
معرض الهوية ومخرجات Storybook داخليان؛ لا يُنشران مع منتج المناقصات.

## الاستعمال في منتج آخر

```bash
# داخل الحزمة: ينتج ملفاً بإصدار محدد.
npm pack
# داخل المنتج المستهلك، استعمل المسار الفعلي للملف الناتج.
npm install /path/to/toptech-ui-0.1.0.tgz
```

تُرفع الإصدارات لاحقاً إلى سجل npm خاص للشركة عندما يُحدد حسابه.
لا يوجد نشر إلى سجل عام ولا حاجة إليه للتثبيت المحلي.

```tsx
// في Next: مكوّن عميل صغير داخل الهيكل الخادمي، مع بقاء جلب البيانات في الخادم.
'use client';
import '@toptech/ui/styles.css';
import { ThemeProvider, Button, TextField } from '@toptech/ui';

export function Workspace() {
  return <ThemeProvider dir="rtl" theme="light">
    <TextField label="اسم المشروع" hint="اسم واضح للفريق." />
    <Button>حفظ التغييرات</Button>
  </ThemeProvider>;
}
```

- ثبّت الخط `@fontsource/ibm-plex-sans-arabic` في التطبيق وحمّل الأوزان المطلوبة
  محلياً، كما في `gallery/main.tsx`. الحزمة لا تجبر كل منتج على تحميل جميعها.
- CSS جاهز؛ **لا يحتاج المستهلك إعداد Tailwind**. رموز الهوية وإعادة الضبط
  محصورة في `.tt-theme`، وتشمل بوابات النوافذ تلقائياً.
- `ThemeProvider` يملك المظهر والاتجاه (`light` أو `dark` أو `auto` لتفضيل النظام). الاستدعاء خارج المزوّد غير مدعوم.
- `AppShell` يستقبل `items` و`activeHref` و`onNavigate`. مرّر المسار **ومعاملاته**
  حين تغيّر الوجهة؛ مثال Next: router.push في onNavigate، وقيمة مشتقة من
  usePathname/useSearchParams. لا تخزّن نسخة أخرى من حالة الوجهة.
- `Button` افتراضياً `type="button"`؛ إجراء النموذج يحتاج `type="submit"`.
  `loading` يعطّل النقر ويعلن الانشغال؛ مرّر نصاً يشرح الانتظار.
- كل `DialogContent` و`SheetContent` يحتاج Title وDescription من العائلة نفسها.
- `SheetContent side="start"` يتبع اتجاه اللغة، و`end` للوحة المحتوى المقابلة.
- Menu للأوامر، Select لقيمة نموذج، Popover لمحتوى قصير، Dialog لقرار مركّز،
  Sheet لتفاصيل أطول. لا تستبدل select بقائمة أوامر لمجرد التشابه البصري.
- `DataTable` يضع التمرير داخل الجدول. هو جدول عرض بسيط؛ الترتيب والفرز
  والترقيم سلوك منتج يجب إضافته صراحةً حين نحتاجه.

## هوية قمم

اتجاهها: **دفءٌ هادئ، وحبرٌ واضح، وأزرق للفعل**. العربية هي نقطة البداية.
العلامة الهندسية قمتان متداخلتان؛ ملفات SVG في `public/brand`، ومعاينتها
في قسم الأسس. التوقيع النصي SVG يحتاج خط IBM Plex Sans Arabic المثبّت؛
العلامة الأحادية مستقلة عن الخط. العلامة المقترحة لا تغيّر شعار المنتج الحي.

المصدر الوحيد للقيم الجديدة: `src/tokens.css`. أسماء دلالية، ومظهران؛
لا نسخ لوحة الألوان في الصفحات. مقياس الخط والفراغ والزوايا وأمثلة الصوت
معروضة في المعرض. توثيق الهوية القديمة يبقى عقد الموقع حتى الترحيل.

**الصوت:** جمل قصيرة، تسميات أفعال محددة، وخطأ يشرح ما حدث والخطوة التالية.
لا تدّع نجاحاً قبل نتيجته؛ المجهول ليس صفراً؛ اللون يرافق النص والأيقونة.

**أيقونات:** Lucide، حجمها الافتراضي 16–20 بكسل، باتجاه وظيفتها. لا تضف
عائلة أيقونات ثانية. لا تُعكس أرقام أو شعارات عند RTL.

**الحركة:** قصيرة وهادئة، مع احترام prefers-reduced-motion. تجنّب تحريك
التنقّل أو تغيّر موضع الإجراء أثناء التفاعل. مساحة اللمس الأساسية 44 بكسل.

## عقد الجودة

```bash
npm run check:design
```

يجمع الأنواع وlint وبناء الحزمة والمعرض وStorybook، ثم فحوص المتصفحات
والمقارنة البصرية وLighthouse CI. يُنادى من `check.sh` و`check.ps1`
وفي وظيفة `design-system` من `ci.yml`.

```bash
npm test                 # Chromium + Firefox + WebKit
npm run test:visual      # Linux ثابت: محلياً عبر Docker
npm run test:update      # يعيد إنشاء الصور؛ راجع فرقها قبل الالتزام
npm run perf             # Lighthouse على معرض الإنتاج
```

- الفحوص تعمل على `gallery-dist` بعد البناء، دون بيانات إنتاج أو شبكة خارجية.
- مرجع الصورة Linux amd64 من الصورة المثبّتة نفسها؛ لا مراجع macOS مختلفة ولا
  تحديث صور تلقائي في CI. أسماء الصور وعدد الفحوص تُحسب من النتائج.
- فحص السلوك يقرأ حدود العنصر وتركيزه واختياره؛ لا تكفي لقطة أو HTTP 200.
- الإتاحة الآلية لا تغني عن قارئ شاشة وتجربة بشرية؛ المعرض يوفّر الأمثلة لذلك.
- Lighthouse يقيس **المعرض فقط** على المكتب والجوال بمحاكاة اتصال بطيء. الحدود في `lighthouserc.cjs` أهداف للإصدار،
  وليست ادعاء تحسن سرعة المناقصات. بعد الترحيل تُوصل الصفحات الحقيقية
  وقياسات المستخدمين؛ زمن API خارج نطاق هذه الحزمة.
- نتائج الأداء محلية في `.lighthouseci/reports`؛ لا تُرفع إلى خدمة خارجية.
- اعتماد فرق بصري يراجع الصورة الناتجة، لا يكتفي بتشغيل `test:update`.

## كيف يطوّر وكيل AI ميزة

1. اقرأ هذا الملف وقالباً قريباً في Storybook.
2. ركّب الصفحة من صادرات `@toptech/ui`، مع بياناتها وحالاتها.
3. أي سلوك عام جديد يُضاف هنا ويُفحص هنا؛ لا نسخة Dropdown مخصّصة داخل الصفحة.
4. حافظ على الجلب في الخادم، واجعل الجزء التفاعلي صغيراً.
5. أثبت فشل الحارس على العطب ثم صحّة الإصلاح. حدّث الصور فقط لتغيير مقصود.
6. إصدار جديد للحزمة، ثم ترقية المستهلك وتجربة رحلاته. لا دفع كسر إلى الجميع.

## خطة الترحيل

ابدأ بالقوائم والنوافذ، ثم الحقول والأزرار، ثم هيكل التنقّل، ثم القوالب.
لكل دفعة رحلة مستخدم مكتملة ومرجع بصري. حافظ على قواعد البيانات والإجراءات
والروابط الحالية. موافقة شكل المعرض ليست إثبات صلاحية دمجه بالمنتج؛ الدمج
يحتاج فحوص المنتج أيضاً، وفق `docs/DESIGN_SYSTEM.md` في جذر المستودع.

## القوالب الجاهزة

`AppShell` لهيكل المنتج، و`ListPage` للقوائم، و`DetailPage` للتفاصيل،
و`SettingsPage` للإعدادات، مع `PageHeader` و`PageSection` لتركيب الأقسام.
أمثلة حية في Storybook وقسم القوالب بالمعرض. هذه قوالب أنماط شاشات
قابلة للتركيب لكل أداة؛ منطق المناقصات أو المحادثة أو تحليل الملفات ليس
جزءاً عاماً منها. كل منتج يربط بياناته وصلاحياته وإجراءاته.

`verify:consumer` يقارن الإصدار المضغوط في web بالمخرجات الحالية؛
لا يكفي إصلاح المصدر وإبقاء المستهلك على حزمة بائتة.
